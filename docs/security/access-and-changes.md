# תיעוד גישה ושינויים — Between

_מקור אמת לשאלה: אילו נתונים קיימים, מי ניגש אליהם, איך שינויים מאושרים, ומה מתועד._
_עודכן לאחרונה: 2026-08-04. בעלים: איה._

**שלב:** טרום-השקה (pre-launch). התפעול הוא איה + קלוד תחת אישור (gate) של איה. אין צוות פיתוח נוסף עם גישת כתיבה לפרודקשן.

**חשוב:** זה מסמך פנימי — לא תקן (ISO/SOC 2) ולא הצהרה משפטית. הפוזיציה המשפטית המחייבת (חוק הגנת הפרטיות + תיקון 13, דלת 0) בבעלות לינה.

---

## 1. אילו נתונים קיימים

| טבלה (Supabase) | מה נשמר | מידע מזהה (PII)? |
|---|---|---|
| `knowledge_chunks` | טקסטים תיאורטיים ל־RAG | אין |
| `user_conversations` | מטא-דאטה של שימוש: מזהה שיחה, `message_count`, דגלי אירועים (`had_summary`, `pdf_downloaded` וכו') | מקושר ל־`user_id` בלבד — לא תוכן שיחה |
| `therapist_cases` | `user_id` + `label` (שם תיאור למקרה) | ה־label נכתב ע"י המטפל — עלול להכיל טקסט חופשי |
| `case_consultations` | `user_id`, `case_id`, `mode`, `theorists`, `anonymized_text` | **הטקסט הגולמי אף פעם לא נכתב** — רק גרסה מאונונמת (`lib/anonymize.ts`) |

**עיקרון מפתח:** חומר קליני של מטפלים עובר אנונימיזציה לפני כתיבה ל־DB. הטקסט הגולמי חולף (ephemeral) — לא נשמר בשרת.

---

## 2. מי ניגש

| גורם | רמת גישה | מנגנון |
|---|---|---|
| משתמש מאומת | קורא/כותב **רק את השורות שלו** | כל שאילתה `.eq('user_id', user.id)` + Supabase auth (token) |
| `service_role` (שרת בלבד) | גישה מלאה — מפתח בצד שרת, לא נחשף ללקוח | `SUPABASE_SERVICE_ROLE_KEY` ב־env של Vercel |
| `anon` (לקוח לא מאומת) | חסום ל־`knowledge_chunks`; ל־`user_conversations` — SELECT בלבד | REVOKE/GRANT מפורש (הוקשח מאי 2026) |
| איה | בעלים — גישה מלאה ל־Supabase/Vercel/GitHub דרך החשבונות שלה | |

**צד ג' עם גישה למידע:** Supabase (אחסון) · Vercel (הרצה) · Anthropic/OpenAI/Gemini (עיבוד תוכן שיחה) · HuggingFace (embeddings) · Resend (אימיילים תפעוליים בלבד — דוחות סוכנים, לא מידע משתמש).

---

## 3. איך שינויים מאושרים

- **קוד:** כל שינוי עובר git. קלוד מתאר → איה מאשרת → מבצע. **אין push לפרודקשן בלי בקשה מפורשת של איה.**
- **פריסה (deploy):** אוטומטית דרך Vercel על push ל־`main`.
- **סכמת DB / הרשאות:** שינוי טבלה חדש חייב לכלול REVOKE/GRANT מפורש — לא לסמוך על ברירת המחדל של Supabase (ראה MEMORY.md).
- **סודות (secrets):** מפתחות ב־env של Vercel בלבד. לא בקוד, לא ב־git.

## 4. מה מתועד — ומה חסר

**קיים היום:**
- **היסטוריית קוד** — git log (מי שינה מה, מתי, למה).
- **היסטוריית פריסה** — Vercel deployments (מי דחף, מתי, איזה build).
- **לוגים תפעוליים** — Supabase logs (שאילתות, שגיאות) + Vercel runtime logs.

**פערים ידועים (לסגירה כשמתקרבים להשקה):**
- אין יומן ייעודי לגישה למידע משתמש רגיש (מי קרא `case_consultations` ומתי) — מעבר ללוגים הגולמיים של Supabase.
- אין תיעוד פורמלי של שינויי הרשאות DB לאורך זמן.
